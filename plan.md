# ggrust plan

Rust plotting engine with a lets_plot-compatible Python API, built for cellestial.
Rules of engagement: [AGENTS.md](AGENTS.md). Lessons: [memory/](memory/README.md).
ggplot2 extension features (ggnewscale, ggbeeswarm, ...): [extensions.md](extensions.md).

## Decisions (agreed with the user)

| Topic | Decision |
|---|---|
| Python API | lets_plot-compatible subset. cellestial port = import swap |
| Parity | Visual and logical parity with lets-plot by default. Apparent lets-plot bugs (legend/geom overflow etc.) are noted, checked against ggplot2, and asked about when unclear; deviations recorded here (decided 2026-10-30) |
| Code quality | Not lets-plot's bar: comprehensive type hints (`ty`), NumPy docstrings, first-class solution-oriented errors. May be finished in step 7.0 after features (decided 2026-10-30) |
| Interactivity | Rust renders everything; tiny embedded vanilla-JS runtime for tooltips + zoom/pan; canvas for dense point layers |
| Build | maturin (PyO3 wheel) + uv |
| Repo | `datavil/ggrust`, import name `ggrust` |
| Data transfer | Arrow PyCapsule interface (polars, pandas, pyarrow, dict of numpy), zero-copy where possible. No JSON for data |
| Spec transfer | Spec (without data) crosses as a JSON string parsed by serde_json: tiny, one parser for fixtures and live calls, no pythonize/pyo3 version lock |
| Fonts | One embedded open font so text measurement and PNGs are identical on every machine |
| Custom fonts (7.1b) | Agreed with the user (2026-11-04): `register_font(path, family=None)`, `register_font_dir(path)`, `registered_fonts()` fill one process-wide, append-only registry (layout measures through free functions, so per-plot font data would touch every layout module; it holds only what the user registered). Family from the font's `name` ID 1, faces (plain/bold/italic/bold italic) from `OS/2`; `.ttc` collections register every face. No system font lookup, so output stays deterministic. Registered names win over the Liberation aliases (`Arial`, `sans`, ...); unknown names fall back to Liberation Sans with a did-you-mean warning; a missing face draws the nearest registered one (slant first, as CSS) and warns. Every output uses the same face: layout, PNG (resvg font database), PDF (subset embedded, CFF too), SVG and HTML (subset embedded as `@font-face` with `unicode-range` and a `kern` table; the zoom character set only in zoomable HTML). Per-glyph fallback (CJK in a Latin font) is a follow-up. Tests use Liberation Serif (OFL). No fonts are bundled beyond Liberation |
| Categorical level order | From the Arrow data: dictionary order, so polars `Categorical` = first appearance (as lets-plot), `Enum`/ordered pandas = category order. Unordered pandas categoricals keep their category order (ggplot2), a recorded deviation from lets-plot's first appearance (decided 2026-10-28) |
| Tooltip scope (4.2) | General tooltips + axis tooltips as lets-plot; boxplot statistics are lines of the general tooltip (lets-plot `disable_splitting` look), not separate side boxes. No tooltip theme elements, `tooltip_group` or crosshair modes (decided 2026-10-28) |
| PDF export (5.3) | Raster PDF as lets-plot (the PNG at its dpi on one page), written by a small Rust PDF writer: no Pillow needed (decided (user) 2026-10-31). Superseded by lp5.13: vector PDF on the same page size (plan step lp5.13, 2026-11-03) |
| imshow PNG encoding | Encoded in Rust with the fastest deflate; the href decodes to lets-plot's pixels but its bytes differ (parity is visual, not byte-level) (decided (user) 2026-10-31) |
| Tooltip runtime (4.2) | Rust computes targets (scene pixels) and every row's text; the JS runtime builds the grid-bucket hit index at mount (no index in the payload) and draws tooltips as HTML divs over the SVG (decided 2026-10-28) |
| cellestial browser tests (5.4) | cellestial's helper is rewritten on ggrust's HTML; ggrust does not emulate lets-plot's HTML hooks (`plt-container`, `lets-plot.min.js`) (decided (user) 2026-10-31) |
| Stat caching (6.3) | No stat-result cache across subplots: a hit needs equal layer, data, scales, facets and grouping, no cellestial grid has that, and the key would be large and fragile. Only Arrow column conversion is cached (decided (user) 2026-10-31) |
| Line colour along a path (lp2.2) | A line whose colour, size or linetype varies within a group styles each segment from its start point, as ggplot2 4.0.1 (checked in R). lets-plot switches at segment midpoints; not copied. Applies to `geom_line`/`geom_path` and area/ribbon edges (decided (user) 2026-11-01) |
| Overflow guards | Deviation from lets-plot and ggplot2 (both overflow; surveyed 2026-11-01). Only plots that would overflow change: key legends reflow into more columns/rows within 50% of the plot across (all but a 50 px panel for a user `guide_legend(ncol/nrow)` grid), then wrap labels narrower (30, 20, 14, 10 chars), then keep the first keys plus a "+K more" entry; outside legends stay inside the plot along their side. Stacked legends share the budget. Discrete axis labels needing more than 1/2 of the plot (x height, y width) wrap at spaces (x into each tick slot, laid out flat), else are cut in the middle with "..."; numeric labels are never cut. Title and subtitle wrap at spaces (over-long words break) to the room right of the panel. Geoms stay clipped to the panel (as both references). Facet panels fit their axis labels too (the budget split among the axis bands). Not yet: colorbars, gggrid collected legends and titles (decided (user) 2026-11-01) |
| Axis title angle | `theme(axis_title*=element_text(angle=...))` turns the title and its band, as ggplot2; lets-plot ignores it (lets-plot#1504). `hjust`/`vjust` place the title along its axis turned by its angle (ggplot2 `rotate_just`), so `vjust` moves a horizontal y title; unset they centre it (ggplot2 inherits `vjust=1`: top) (decided (user) 2026-11-01; vjust by lp3.5) |
| Identity bar stacking (lp3.1) | `geom_bar`/`geom_histogram` with `stat="identity"` and no `mode` stack every row (`mode="all"`), as ggplot2: rows of one group at one x stack. lets-plot's default `mode="groups"` overlaps them (lets-plot#1398). Other geoms and stats keep `groups` (density band ends and ydensity repeat x inside a group) (planned step lp3.1, 2026-11-01) |
| Free facet stat ranges (lp3.2) | On a free facet axis, binned and density stats use the panel's own range, as ggplot2; lets-plot bins every panel over the whole plot's range (lets-plot#1443). Shared axes unchanged (planned step lp3.2, 2026-11-01) |
| End axis labels (lp3.3) | An end x label that would run past the plot's edge gets room (the panel narrows), a ggrust deviation: lets-plot and ggplot2 4.0.1 both cut it (lets-plot#906). Text geoms stay clipped to the panel, as both (lets-plot#339) (decided (user) 2026-11-01) |
| Shared discrete axes (lp3.6) | `gggrid(sharex/sharey)` shares discrete axes too (union of categories as limits); lets-plot shares only continuous ones (lets-plot#1015) (planned step lp3.6, 2026-11-01) |
| Panel minimum in grid cells | Inside a `gggrid` cell a panel shrinks to what the cell leaves (at least 1 px), as ggplot2/patchwork; standalone plots keep lets-plot's 50 px `GEOM_MIN_SIZE`. lets-plot keeps 50 px in cells too, so thin cells (cellestial annotation tracks) ran past their cell and their axis titles centred off the visible strip (decided (user) 2026-11-01) |
| scale_size_area | Circle area proportional to the value (`max_size * sqrt(|v| / max|v|)`, ggplot2 `rescale_max` + `abs_area`: negative values draw by their absolute value); lets-plot scales the diameter linearly (lets-plot#1452) (decided (user) 2026-11-01) |
| Legend stacks wrap | Stacked legends too long for the budget wrap into more stacks side by side (in order, greedy) when those fit the budget across; otherwise the earlier share/reflow/cut rules apply (lets-plot#1506) (decided (user) 2026-11-01) |
| Smooth band SE | Deviation from lets-plot, chosen by the user (2026-11-01): `geom_smooth` bands use each model's own standard error, as ggplot2 (polynomial: `x0'(X'X)^-1 x0`; loess: `s * |l(x0)|`, df `delta1^2/delta2`). lets-plot uses the straight-line SE for every method. Curves are unchanged (lets-plot's fits) |
| Toolbar style (`ggtb`) | Deviation from lets-plot's look, chosen by the user (2026-11-01): "soft frost ink", a 10 px rounded translucent white bar with a hairline border and faint shadow, 24 px buttons, grey icons, an ink-filled (rgb 44, 44, 42) selected tool and a divider before Reset. Same tools, icons and place, and the same 33 px above the plot |
| Layer toggles (`ggtb(layers=...)`) | A ggrust extension (lets-plot has none), from the user's idea while zooming cellestial spatial plots. Opt-in: `ggtb(layers=True)` or a dict of labels to layer indices (`{"tissue": 0, "spots": 1}`), so the default toolbar stays lets-plot's. A Layers button opens a menu of checkboxes; labels default to the geom name (`imshow` for `geom_imshow`), numbered from the second use. Each `gggrid` subplot has its own list and labels go by index in every subplot. Legends stay as drawn (decided (user) 2026-11-02) |
| Arrow axes | A ggrust extension (lets-plot has none), agreed with the user (2026-11-03) for cellestial's UMAP corner arrows: `element_line(arrow=arrow(...), extent=0.25)` on `axis_line`/`_x`/`_y`; `extent` is a fraction of the panel from the bottom-left corner (not ggh4x data units, not a `guide_axis`). Drawn by the layout in pixels, so zoom never moves it |
| ggnewscale (`new_scale_color()`, `new_scale_fill()`, `new_scale(aes)`) | A ggrust extension (lets-plot has none, ggplot2 needs ggnewscale), design agreed with the user (2026-11-04, step ex1.3). Style scales are keyed by aesthetic plus scale group (`ScaleKey`). Python resolves the `+` order: layers and scales after a marker carry `"scale_group": {"color": 1}`, guides and labs after it use the key `"color:1"`; plots without a marker serialize as before. Legends of different groups never merge, even with equal titles (ggplot2 merges equal title + labels). Position aesthetics are rejected. `gggrid(guides="collect")` still merges equal legends by content |
| Extension sizes (ggplot2 units) | Chosen by the user (2026-11-04, step ex1.6): when an R extension's default sizes are ggplot2 units (ggdist's interval widths and point fattening), ggrust converts the defaults so the plot looks as in R (a ggplot2 line width of 1 is 2.845 px, ggrust's size 1 is 2.2 px; points 3.8 px vs 2.2 px per unit). Parameters stay in ggrust units. |
| Statistics labels (ggpubr / ggpmisc) | Chosen by the user (2026-11-04, step ex1.7): p-values are R's `format.pval(p, digits = 2)` per value; multiple-comparison adjustment is opt-in (`p_adjust_method`, default unadjusted as ggpubr); labels are plain text placed by ggpubr's rule (also for `stat_poly_eq`); stats may read the discrete x level names (`StatContext.x_levels`) to resolve level names given as options. |
| Dendrograms (`hclust`, `scale_*_dendro`) | Agreed with the user (2026-11-04, step ex1.9): legendry names (`scale_x_dendro`, `guide_axis_dendro`; ggh4x's `guide_dendro` is deprecated); the tree is precomputed and passed to the scale: primarily a scipy linkage (`ClusterTree.from_linkage(Z, labels)`, scanpy's `uns["dendrogram_<group>"]["linkage"]`, scipy `dendrogram()` leaf order and coordinates; scope change approved by the user the same day), with `ggrust.hclust()` (R `hclust` results) as the fallback, which orders the levels; the tree is drawn in the axis band (past the labels) or, with `side="opposite"`, in a top/right band, so `gggrid(align=True)` needs no change; facets draw no tree yet. |
| Spec accessors | Chosen with the user (2026-11-04): ggplot2-style escape hatches as read-only properties (`p.data`, `p.mapping`, `p.layers`, `p.scales`, `p.theme`, `p.labels`, `p.size`, `p.facet`, `p.coord`, `p.guides`; `layer.geom`/`stat`/`data`/`mapping`/`params`; grid `figures`, `layout`, `ncol`, `nrow`, `size`, `theme`, `labels`, `plots()`, `plot_paths()`, `grid[i]`, `grid[row, col]`), changes only as copies (`with_data`, `with_figure`, `with_layout`), and engine-backed `p.layer_data(i)` / `p.build()` (on the plot, not the layer: one `LayerSpec` can sit in many plots, so it has no back-reference). Plain dicts and tuples, not typed spec objects. Grids have no `build()` |
| patchwork extras (`gggrid`, `inset_element`) | Agreed with the user (2026-11-04, step ex2.3): patchwork's features as keyword arguments on `gggrid` (`design=`, `tag_levels=`, `tag_level=`), not `plot_layout()`/`plot_annotation()` objects; tag prefix and suffix come from lets-plot's `theme(plot_tag_prefix/suffix)`. `plot + inset_element(q, ...)` keeps `plot` the plot that later `+` changes. Single-plot tags (`labs(tag=)`, `plot_tag*`) follow lets-plot and were added in the same step. |
| Side panels (ggside, `ggmarginal`) | Agreed with the user (2026-11-05, step ex2.2, rescoped around heatmap annotation tracks): ggside's R names (`geom_xsidetile`, `scale_xsidey_discrete`, `ggside(x_pos=, y_pos=)`); one band per side whose tracks are levels of its own discrete scale (a side tile without a cross mapping is the track of its fill column); separate fill scales through `new_scale_fill()`; bands sit between the panel and the axis and count as axis area for `gggrid(align=True)`; facets drop side layers for now (warning); lets-plot's `ggmarginal()` (lp5.6) is a thin Python layer writing lets-plot's own spec keys onto the same engine. cellestial keeps its AnnData ordering and binning. |
| Several side bands per axis (9.10) | Agreed with the user (2026-11-06): extend ggside in its style, not a ComplexHeatmap object. Per-layer `side_pos=` (overrides `ggside()`), `side_band=` (named bands stack outward in plot order), `side_size=` (share of the panel); `scale_*side*_*(side_pos=, side_band=)` targets one band, most specific wins. A deviation from ggside (one band per axis). |
| Notebook setup | Agreed with the user (2026-11-05): no `LetsPlot` class (ports delete `setup_html()`); `ggrust.display("html" \| "svg" \| "png")` picks the notebook output, kept out of `__all__` so star imports do not shadow IPython's `display`. |
| Plot files (`.ggrs`) | Agreed with the user (2026-11-05): `ggsave(plot, "x.ggrs")` and `ggload("x.ggrs")` save and open the plot object itself (lets-plot and ggplot2 have no safe equivalent; R uses `saveRDS`). A zip: `manifest.json` (format version, SHA-256 + size per entry), `plot.json` (allowlisted ggrust classes as tagged JSON), `data/*.arrow` (Arrow IPC, restored as polars, pandas or pyarrow), `fonts/*` (registered fonts the plot names, embedded). Loading runs no code; callables (`sec_axis` transforms) refuse to save with the spec path (sampling them is for later); signing (Ed25519) is for later. Extension `.ggrs` only; names `ggsave`/`ggload`, no `save_plot` (user, 2026-11-06). See `memory/plot_files.md`. |
| No `ggbunch()` | lets_plot's free layout is not ported (2026-11-09, user): `inset_element(plot, left, bottom, right, top, align_to="full")` on an empty `ggplot() + theme_void() + ggsize(w, h)` places plots by figure fractions with overlap, which covers it; `gggrid(design=)` covers non-overlapping free layouts. The `GGBunch` stub points there. |
| HTML canvas threshold | Point batches with more than 5,000 drawable markers (2,000 for `ggtb()` plots) go to the HTML canvas, down from 50,000 (2026-11-06): mid-sized SVG scatters made HTML ~3x larger than lets-plot. See `memory/html_canvas_points.md` |

## Scope: what cellestial actually uses

Counted from `cellestial/` source (calls per symbol). This drives priority.

- **Spec objects:** `aes` (130), `PlotSpec`/`LayerSpec`/`FeatureSpec`/`FeatureSpecArray`/`SupPlotsSpec`, `as_dict()`, `+`, `gggrid` (19), `ggsize` (11), `labs`/`xlab`/`ylab`/`ggtitle`
- **Theme:** `theme` (31), `element_blank` (46), `element_text` (36), `element_rect`, `element_line`, `theme_classic`, `theme_bw`, `theme_void`; params `legend_position`, `axis_text_*`, `axis_title_*`, `axis_line`, `panel_background`
- **Interaction:** `layer_tooltips` (26), `ggtb` (25)
- **Geoms:** point, path (9), segment (7), text (6), tile, boxplot, violin, raster, rect, polygon, vline, hline, line, bar, histogram, label, text_repel, label_repel, bracket, area_ridges, imshow, function, blank
- **Positions:** dodge, jitterdodge (+ identity, stack, jitter implied)
- **Scales:** x/y continuous (21), x/y discrete, `scale_y_log2`, `scale_y_reverse`, color/fill: brewer (11), viridis (13), hue (6), gradient, gradient2, gradientn, manual, continuous; `scale_size`; `guides`/`guide_legend`
- **Coords / facets:** `coord_fixed`, `coord_flip`, `coord_cartesian`, `facet_wrap`
- **Output:** `_repr_html_`, `to_svg`, `to_png`, `to_html`, `ggsave`, `LetsPlot.setup_html`

Not needed (skip): livemap / GIS / geocoding, Kotlin/JVM/Compose/Swing/Batik, `bistro` (corr_plot, qq_plot, ...),
waterfall, pie, contour/density2d, smooth/regression, polar coords, sampling UI, frontend contexts beyond Jupyter + standalone HTML.

## Implementation plan

Each step = one or more commits on `main`, tests green, visuals checked, bug-hunt agents run.
Steps inside a phase are ordered; each builds on the previous.

## Performance strategy (honest)

- Biggest structural win: lets-plot serializes data to JSON in Python, then parses it in Kotlin/JS.
  ggrust passes Arrow buffers to Rust with no serialization.
- Native Rust stats (KDE, binning, boxplot) with rayon across groups and subplots.
- SVG writing with pre-sized buffers and `ryu` float formatting; PNG via tiny-skia directly from the scene (no SVG round trip).
- HTML: dense points as a base64 typed array drawn on canvas instead of 1M SVG nodes.
- No GPU on the dev server; GPU only appears client-side (canvas/WebGL). No server-side GPU work planned.
- Benchmarks always state N drawn, sampling settings, output format, hardware, cold vs warm.
